پارسی‌نگار ویرایشگر فارسی مارک‌داون است: میزکار تک‌صفحه‌ای راست‌به‌چپ که هم‌زمان با تایپ، متن را به‌شکل نهایی نشان می‌دهد. سندها روی همین مرورگر ذخیره می‌شوند، پوشه‌بندی می‌شوند و هر وقت لازم بود یک‌جا خروجی گرفته می‌شوند — بدون حساب کاربری و بدون سرور.

## ویژگی‌ها

- **نوشتن راست‌به‌چپ واقعی:** جهت هر خط جداگانه تشخیص داده می‌شود؛ خط فارسی راست‌به‌چپ و خط انگلیسی/کد چپ‌به‌راست می‌ماند. قلم وزیرمتن و ارقام فارسی در سراسر برنامه.
- **نمای زنده هنگام تایپ:** نشانه‌های مارک‌داون پنهان می‌مانند و متن به‌شکل نهایی دیده می‌شود؛ نشان هر خط فقط وقتی نمایان می‌شود که روی همان خط ویرایش کنید. عنوان‌ها، نقل‌قول، کد (۱۴ زبان با دکمه رونوشت)، تصویر، جدول، پاورقی، اندرز و شعر.
- **فهرست‌های جمع‌شونده:** فهرست مرتب، نامرتب و بازبینه با کلیک روی نشان والد جمع و باز می‌شوند؛ بازبینه‌ها با کلیک تیک می‌خورند و Tab/Shif+Tab سطح‌ها را جابه‌جا می‌کند.
- **نقشه ذهنی:** سندهای تمام‌فهرستی وسط صفحه به‌صورت نقشه تعاملی راست‌به‌چپ دیده می‌شوند؛ دابل‌کلیک متن گره را ویرایش می‌کند و با دکمه‌ها و درگ ساختار عوض می‌شود — همه بلافاصله در متن همان سند ذخیره می‌شوند.
- **ویرایش درجا جدول:** کلیک روی هر سلول همان‌جا ویرایشش می‌کند (ثبت با Enter، لغو با Escape، چرخش با Tab).
- **تمام‌صفحه نوشتن:** پنهان‌شدن همه بخش‌ها جز ویرایشگر، با دکمه شناور خروج.
- **پوشه‌بندی:** پوشه‌های تودرتو (حتی خالی)، انتقال سند بین پوشه‌ها، چینش فهرست، وارد کردن گروهی پوشه از دستگاه (با به‌روزرسانی هوشمند) و دانلود یک‌جای کل کتابخانه با همان درخت پوشه در قالب zip.
- **خروجی گرفتن:** دانلود هر سند به‌صورت مارک‌داون یا سند HTML مستقل (راست‌به‌چپ، با پوستهٔ انتخابی).
- **جست‌وجو و جایگزینی:** در همین سند، با شمارنده و پرچم‌های حساسیت به حروف، کلمهٔ کامل، باقاعده و «فقط در انتخاب»؛ میان‌برهای مستقل از چیدمان صفحه‌کلید (`Ctrl+F`).
- **حالت فقط-خواندن:** قفل هر سند از منوی سند یا نوار منو؛ راهنما و تاریخچه همیشه فقط-خواندن‌اند.
- **شخصی‌سازی:** چهار پوسته (روشن، تیره، دستگاه، سپیا)، اندازهٔ قلم ۱۲ تا ۲۴ و جهت متن — همه پایدار بین نشست‌ها.

## اجرا

```sh
npm install
npm start     # سرور ایستا روی ریشهٔ پروژه، سپس باز کردن آدرس اعلام‌شده
```

نیازمندی: Node نسخهٔ ۲۰ یا بالاتر. سرور باید ریشهٔ پروژه را سرو کند تا `node_modules/` (برای importmap) و `bootstrap.json` در دسترس باشند. `npm start` از `--single` استفاده می‌کند تا مسیرهای SPA هم به `index.html` برگردند.

## استقرار

```sh
npm run build # مونتاژ dist برای انتشار (همان کاری که Pages CI می‌کند؛ esbuild فقط اینجا)
```

توسعه همیشه مو‌جول‌های ES خام و بدون باندلر است؛ باندل (esbuild) فقط در «زمان استقرار» اجرا می‌شود تا انتشار روی Pages تقریباً ده‌ها به‌جای صدها درخواست بگیرد (تصمیم §۴۵ در `docs/decisions.md`). هر واحدها و هدف‌های importmap خودشان `index.js` تک‌فایلی می‌گیرند و خروجی دقیقاً در همان مسیرهای درخت خام می‌نشیند تا importِ پویای زمان اجرا، خوانده‌شده‌های اولیه (`bootstrap.json`، مانیفست‌ها، sprite و css MindElixir) به‌هم نخورند.

## آزمون

```sh
npm test
```

سوئیت با `node:test` و `jsdom` اجرا می‌شود: تست‌های سطح اپ در `tests/`، تست‌های افزونه‌ها کنار کدشان و تست‌های UI در `src/ui/tests/`. رفتارهای چیدمانی/دیداری (که jsdom ندارد) با پروب گذرای کرومیوم headless راستی‌آزمایی می‌شوند.

```text
parsinegar/
├── index.html            # لودر Host + importmap
├── bootstrap.json        # تنها محل تعریف آداپترها، افزونه‌ها و مسیر UI
├── package.json          # وابستگی‌ها (npm + GitHub)
├── scripts/              # مونتاژ استقرار (build-dist.mjs، فقط در CI)
├── CHANGELOG.md          # تاریخچهٔ تغییرات (در اپ هم باز می‌شود)
├── LICENSE               # MIT
├── public/               # فایل‌های ایستا: فونت وزیرمتن، تم‌های سطح سند
├── docs/                 # ABOUT، architecture، decisions، userGuide و مستندات UI
├── src/app/              # میزبان اجرا: main، config-source، env-source، module-loader
├── src/ui/               # رابط کاربری: index، manifest، assets، components، pages، i18n، utils، tests
├── src/plugins/
│   ├── app/              # مالک مسیرهای اپ (۰.۱.۰)
│   ├── documents/        # چندسند روی pey.storage (۰.۵.۰)
│   ├── settings/         # ترجیحات کاربر روی pey.storage (۰.۳.۰)
│   ├── export/           # خروجی HTML مستقل و zip چندسندی (۰.۲.۰)
│   ├── filesystem/       # دسترسی به فایل/پوشهٔ دستگاه، محلی فعلاً (۰.۲.۰)
│   └── sync/             # همگام‌سازی با مخزن گیت، محلی فعلاً (۰.۳.۰)
└── tests/                # آزمون‌های سطح اپ و یکپارچه‌سازی
```

## معماری

پروژه روی معماری **Bonyan نسخهٔ ۰.۱۱** و چارچوب **Pey** ساخته شده: منطق دامنه در افزونه‌هاست (`src/plugins/`) و رابط کاربری (`src/ui/` روی `pey.webui`) فقط از مسیر سرویس‌ها با آن‌ها حرف می‌زند — هرگز دورشان نمی‌زند. UI فریم‌ورک ندارد: وب‌کامپوننت‌های بومی، ماژول‌های ES بومی و importmap، بدون هیچ ابزار ساختی در توسعه (باندل فقط در استقرار، §۴۵). تنها محل معرفی آداپترها، افزونه‌ها و مسیرهای UI فایل `bootstrap.json` است و `index.html` مالک importmap است.

| افزونه | نوع | نسخه | مسئولیت |
|---|---|---|---|
| `parsinegar.documents` | product | ۰.۵.۰ | چندسند مارک‌داون (CRUD، عنوان یکتا، پوشه‌بندی، پرچم فقط-خواندن) روی `pey.storage` |
| `parsinegar.settings` | product | ۰.۳.۰ | ترجیحات کاربر (پوسته، جهت، قلم) روی `pey.storage` |
| `parsinegar.export` | feature | ۰.۲.۰ | خروجی HTML مستقل و zip چندسندی مارک‌داون |
| `pey.sync` | infrastructure | ۰.۳.۰ | همگام‌سازی دستی سندها با فضای کاربر (بک‌اند git، هویت مسیر)؛ محلی می‌ماند تا مستقل منتشر شود |
| `parsinegar.app` | — | ۰.۱.۰ | مالک مسیرهای اپ |
| `pey.filesystem` | infrastructure | ۰.۲.۰ | دسترسی به فایل/پوشهٔ دستگاه؛ محلی می‌ماند تا مستقل منتشر شود |

کتابخانه‌های کلیدی:

- **رابط و هسته:** `@pey/core` (v0.2.2)، `pey.webui` (v1.0.0)، `pey.router` (v1.0.0)، `pey.storage` (v0.4.0) — مستقیم از GitHub، پین‌شده.
- **ویرایشگر:** CodeMirror 6 با گرامر lezer برای تجزیهٔ مارک‌داون.
- **رندر فارسی:** `pey.markdown` (v1.0.0) با افزونه‌های `parsneshan` (v0.2.0) برای اندرز، لیست فارسی و شعر.
- **فشرده‌سازی:** `@zip.js/zip.js` برای خروجی zip (بدون worker، با CompressionStream بومی).
- **توسعه:** `node:test` و `jsdom` (فقط dev).

نکته‌ها:

- سند معماری: `docs/architecture.md`؛ تصمیم‌های ثبت‌شده: `docs/decisions.md` (هر رفتار تازه اول آنجا تصمیم می‌شود، بعد در کد).
- این فایل، `CHANGELOG.md` و `ABOUT.md` داخل خود اپ هم از منوی «راهنما» به‌صورت سند فقط-خواندن باز می‌شوند.
- قراردادها: ESM بومی بدون باندلر، نام‌گذاری kebab-case، تست برای هر رفتار، بدون کامنت تزئینی در کد.
