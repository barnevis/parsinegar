# Editor helpers (`components/editor/`)

This folder owns everything that creates and styles the CodeMirror Markdown view. It contains no custom elements on purpose: a `PeyElement` child cannot be nested declaratively (connect-before-insertion plus the render-cycle rule forbid it), so the owning page renders the host node and mounts the view through the controller factory here.

## Modules

- `markdown-view.js` — `createMarkdownView(host, options)` controller factory (`getValue`, `setDocument`, `focus`, `undo`, `redo`, `gotoLine`, `visibleLine()`, `insertMark(kind)`, `setSearch(spec)`, `searchStep(spec, direction)`, `searchReplaceOne(spec)`, `searchReplaceAll(spec)`, `setReadOnly(locked)`, `isReadOnly()`, `destroy`); owns the extension list, the layout-independent select-all handler, the `direction` option (`rtl`/`ltr`/`auto`, default `rtl`; `auto` sets `dir="auto"` and detects per line while keeping an rtl base, so the caret stays right on empty lines), the `fontSize` option (integer pixels 12–24, default 16) and the `colorScheme` option (`light`/`dark`/`sepia`, default `light`). Editing extensions: `indentWithTab` (Tab/Shift+Tab; Alt+Arrow line moving arrives through the default keymap), `closeBrackets()` plus `closeBracketsKeymap` (bracket pairing, pair-aware Backspace), `quote-pairs.js` for quotes/backticks (below) and the plain-Enter list continuation below. `insertMark` reuses the `toggle-mark.js` commands programmatically (unknown kinds fail safe with `false`). `visibleLine()` answers the first visible line at the editor top in viewport coordinates, so it works no matter which ancestor scrolls. Read-only locking (`readOnly` option, `setReadOnly`) lives in a compartment driving both `EditorView.editable` (drops DOM editability, `setDocument` keeps working) and `EditorState.readOnly` (library commands refuse on their own), so toggling never remounts and undo history survives; while locked, the keydown handler lets only select-all through, `insertMark`/`undo`/`redo` refuse, replacements report `replaced: 0` with truthful counts, and task toggles freeze — selection, scrolling, copy, find and stepping keep working. Search runs on the `search()` extension (state plus match highlight only — the default panel and keymap stay out; the menubar form owns the UI): `setSearch` applies the query and counts (`{ invalidRegexp, current, total }`), `searchStep` moves the selection through the scope with wrap, `searchReplaceOne` replaces the match under the cursor (or advances when on none, `replaced: 0`), `searchReplaceAll` replaces the whole scope in one undoable transaction; all report post-op counts. Match washes are amber in every scheme (light rules here, dark/sepia in `editor-theme.js`, which loads after the base theme so it wins there).
- `editor-theme.js` — `editorColorScheme(scheme)`: dark and sepia CodeMirror overrides (text, selection, cursor, active line, gutters, highlight wash, search-match washes). Values are literals mirroring `public/theme.css` because head-injected editor styles cannot resolve shell-scoped tokens; the light scheme needs no extension. Loads after the base theme in `markdown-view.js`, so its `.cm-searchMatch` rules win over both the library base theme and the light rules there.
- `live-preview.js` — single-pane live preview: a private `HighlightStyle` with stable `parsi-*` classes (never the generated hashed classes), the hiding/styling theme, quote/list/code-fence line decorations, list-marker widgets and a mark-reveal plugin; `livePreviewExtensions()` composes them. Hidden marks reopen only where the cursor (or selection) overlaps them — or anywhere inside the same reveal span, so standing on formatted text reveals its delimiters (headings count as one span: anywhere on a `# Title` or either setext line reveals its marks); quote and list marks still need exact overlap. Heading and quote marks additionally hide the spaces right after them (`collectExtendedMarkRanges`), otherwise the delimiter space would render at the content size and push the line off the edge while plain lines hug it. List bullets stay rendered until the cursor is on the marker glyphs themselves. A selection-paint plugin (`parsi-selected`) swaps the opaque code backgrounds (inline chips, fence lines) for the selection color wherever a non-collapsed selection touches them, because those backgrounds cover CodeMirror's own selection layer; collapsed cursors never paint. One selector per theme key: comma selectors with `&` never reach the injected stylesheet, and mark decorations nest as their own element (never merged onto syntax spans), so nested selectors must cover both directions.
- `task-list.js` — `- [ ]` / `- [x]` checkbox widgets with click-to-toggle (`ignoreEvent() === false` so the toggle handler runs; position carried on the widget, never measured), `TASK_LINE_PATTERN`, `toggledBox()`; `taskListExtensions()` composes them.
- `code-highlight.js` — fenced-code highlighting: `codeLanguageDescriptions` feeds `markdown({ codeLanguages })` (javascript/typescript/tsx, python, bash, sql, json, html, xml, css, yaml, java, cpp, go, rust, php; lezer languages load lazily, shell parses synchronously), `codeLanguageForInfo(info)` resolves info strings, and `codeHighlightExtensions()` adds token styling with stable `parsi-code-*` classes (light values here, dark/sepia in `editor-theme.js`).
- `code-copy.js` — `collectCodeBlocks(view)` plus `codeCopyExtensions({ t, assetBaseUrl })`: a copy icon button above every non-empty fenced block (content range carried on the widget, never measured), `copyText(text)` with clipboard-plus-textarea fallback, and a transient check state; the plugin rebuilds whenever the copied key changes, so feedback appears and fades through empty dispatches.
- `list-continue.js` — `continueList(view)`: plain Enter with a collapsed cursor at a line end continues `- `/task/`N. `/`>` lines (tasks reopen unchecked, ordered markers increment in ASCII or Persian digits, empty marker-only lines lose the marker instead); anything else returns false so the default newline runs. Runs before CodeMirror's own markdown Enter continuation, which stays as the fallback for mid-line positions.
- `quote-pairs.js` — `pairInput(view, key)`/`deletePair(view)`: `"`, `'`, backtick and `«»` pairing (pair at boundaries, step over twins, wrap selections, Backspace removes empty pairs, single insert before word characters); anything else returns false.
- `line-direction.js` — `resolveLineDirection(text)` plus `isNeutralLine(text)` plus `lineDirectionExtensions(base, forced)`: every visible line gets an explicit direction pinned through line decorations. In `auto` mode lettered lines take their own script direction (`parsi-dir-rtl`/`parsi-dir-ltr`) and letter-less lines take the base (`parsi-base-rtl`/`parsi-base-ltr`); in a forced (`rtl`/`ltr`) mode every line takes the forced base class — even English lines under `rtl` — except fenced code content, which always stays `parsi-dir-ltr` (fence parity is scanned from the document start, mirroring `live-preview.js`). A leading task checkbox is skipped before scanning, so the Latin `x` of `- [x] سه` never decides (bare `- [x]` counts as letter-less, taking the base). The theme pairs each class with a matching explicit alignment. Explicit pinning replaced stylesheet `unicode-bidi: plaintext` on `.cm-line` because Firefox aligns a wrapped continuation row that breaks inside an inline span to the wrong side under `plaintext` plus `text-align: start`, while Chromium parked letter-less `plaintext` lines left regardless of the base.
- `text-highlight.js` — `==highlight==` decorations (inner text plus hidden delimiters, revealed on the active line); the light wash is fixed yellow with pinned dark ink, while dark (lime) and sepia (amber) washes arrive through `editor-theme.js`; multiline spans are not supported.
- `image-view.js` — `collectImagesFrom(state, from, to)` plus `collectImages(view)` and `imageViewExtensions()`: remote `http(s)` images render as inline pictures (`Decoration.replace` over the whole `![alt](src)` span). The cursor/selection touching the span keeps the editable source (same reveal contract as links, `Image` already being a reveal container); relative paths, `data:` URLs and reference-style images (no `URL` child of their own) keep the alt-text rendering; broken pictures swap for their alt text in place. An image nested in a link keeps the outer target (anchor with `target="_blank"`, `rel="noopener"`). Pictures are capped (`max-width: 100%`, `max-height: 16rem`). Pure over the syntax tree — no view — so collection unit-tests against a bare `EditorState`.
- `search-ops.js` — `normalizeSearchSpec(spec)`, `createSearchQuery(spec)` (`{ query }`, `{ query: null }` for empty, `{ error: 'invalid-regexp' }` for bad patterns), `resolveSearchScope(state, spec)` (main selection when `inSelection` is set and non-empty, else the whole document), `collectSearchMatches(state, query, scope)` (precise matches ascending with per-match `replacement`; regexp `$` references expand from the cursor match, mirroring the library rule) and `indexOfMatchAt(matches, pos)`. Pure over public `@codemirror/search` API only (`SearchQuery`, `getCursor`) — no view, no internal query types — so it unit-tests against a bare `EditorState`.
- `link-follow.js` — `linkHrefAt(state, pos)` plus `linkFollowExtensions()`: Ctrl/Cmd+click (or middle-click) on a link label opens its http(s) target in a new tab (`window.open` guarded, silent where unavailable); plain clicks keep placing the cursor. Boundaries bias forward, so a click on the opening bracket still follows; linked pictures navigate through their own anchor and are skipped here. Positions resolve through `posAtCoords` with a `posAtDOM` fallback.

## Contracts

- No module here touches services, the Core, or the Event Bus; options and callbacks arrive as explicit arguments.
- CodeMirror owns its own listeners until the controller's `destroy()` releases them.
- Marks hide with zero font size (never `display:none`) so cursor, selection and bidi ordering keep working at mark positions.
